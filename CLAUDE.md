# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Backend for AutoFacSigo, a university/entrepreneurship project. The company distributes food-industry chemicals (plants, factories, catering, restaurants). This API currently exists for a single purpose: automating the capture of an invoice from Siigo's web app (siigonube.siigo.com) via Selenium browser automation, persisting it to MySQL, and appending it to a local Excel accounting report. There is no public-facing functionality here — the landing page and product catalog live in the separate Angular frontend (`../AutoFac`) and have not been started.

## Commands

- Run the app: `./mvnw spring-boot:run` (or `mvnw.cmd spring-boot:run` on Windows cmd)
- Build: `./mvnw clean package`
- Run tests: `./mvnw test`
- Run a single test class: `./mvnw test -Dtest=ClassName`

Requires a local MySQL instance with a database named `autofacapi` (root user, empty password per `application.properties` — no seed/migration scripts exist, schema is generated by Hibernate via `spring.jpa.generate-ddl=true`).

Requires Chrome installed locally for the Selenium flow (`SeleniumService` launches `ChromeDriver()` in non-headless mode).

## Architecture

Standard layered structure: `controller` → `services` (with an `iDataService` interface implemented by `DataService`) → `repository` (Spring Data JPA) → `entity`. Base package `com.AutoFacApi`. Packaged as a `war` with `ServletInitializer` present (built for deployment to an external servlet container), though `spring-boot-starter-tomcat` is also on the classpath as `provided`.

There is currently one domain entity: `Data` (`entity/Data.java`) — it models one row of a captured Siigo invoice (`numeroFactura`, `cliente`, `nit`, `fechaGeneracion`, `fechaVencimiento`, `valorTotal`, `formaPago`, `medioPago`), all as `String` fields, no validation. It is not a general invoicing or product model — treat any future `Producto`/`Cliente`/`Factura` domain model as new work, not an extension of `Data`.

### The capture flow (the core of this backend)

`DataController.capturar()` (`POST /api/data/capturar`) is the only non-trivial endpoint. It chains three services:

1. `SeleniumService.capturarFactura()` — opens a real Chrome window, logs into Siigo, and **waits for the URL to contain `/invoice/`**. This assumes a human has manually navigated to a freshly created invoice in the opened browser window during the run — this is not a create-invoice flow, only a scrape-an-already-open-invoice flow. Data extraction is by XPath against Siigo's current DOM (`extraerFactura`), so it is tightly coupled to Siigo's UI and will break silently if Siigo changes markup.
2. `DataService.save()` persists the scraped `Data` via `iDataRepository`.
3. `ExcelService.guardar()` appends a row to `C:/selenium/cuentas_prueba.xlsx` (hardcoded absolute Windows path), creating the file with headers on first run.

Other endpoints: `GET /api/data/list` (list all captured rows), `POST /api/data` (raw save, not used by the current frontend flow).

### Known rough edges (be aware, don't silently "fix" without discussing — some may be intentional during active development)

- Siigo login credentials are hardcoded in plaintext in `SeleniumService.login()`.
- `driver.quit()` is commented out in `capturarFactura()` ("Comenta mientras pruebas") — Chrome processes are left running after each capture.
- `hibernate.dialect=org.hibernate.dialect.HSQLDialect` in `application.properties` while the actual datasource is MySQL — inconsistent, though Hibernate autodetects the real dialect from the driver so it's currently a no-op leftover.
- No Spring Security / auth of any kind — every endpoint is open. CORS in `configuration/ConfigurationWeb.java` only allows `http://localhost:4200` (the Angular dev server).
- `ExcelService`'s header row defines "Ultimo proceso" and "Maximo valor facturado" columns that are never populated.
